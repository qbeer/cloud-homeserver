# Config snapshot (for disaster recovery)

This folder mirrors a small, curated set of *non-sensitive* configuration files
from the live stack into the repository, so a repaired or replacement host can
be brought back up without starting from scratch.

- Generated by: `scripts/sync.sh --config` (rsyncs the manifest into `./data`
  and `git add -f`s exactly those files).
- The exact files are listed in `scripts/sync_manifest.txt` and are mirrored
  from `$ROOT_DIR` (default `/mnt/drive`).
- Re-run `scripts/sync.sh --config && git commit` after changing any config to
  keep the snapshot current.

## What is deliberately NOT included

Anything that can be regenerated or that contains credentials / personal data:

- Databases and logs (Sonarr/Radarr/Prowlarr `*.db`, Jellyfin `jellyfin.db` +
  `library.db`, Jellyseerr `db/`, Nginx `database.sqlite` + `keys.json` +
  `letsencrypt/`, Actual `server-files/`, Home Assistant `.storage/` +
  `home-assistant_v2.db`)
- Media covers, thumbnails, caches, library images
- `HomeAssistant/config/secrets.yaml`, `.env` (use `.env.example`)
- Files that embed live credentials and are therefore *not* committed:
  Sonarr/Radarr/Prowlarr `config.xml` (`ApiKey`), Transmission `settings.json`
  (`rpc-password`), Jellyseerr `settings.json` (`sessionSecret`/`apiKeys`),
  Nginx `keys.json` + `letsencrypt/`, Home Assistant `.storage/`.
- /arr application data (library indexes, history, indexer credentials) lives
  in the `*.db` files, which are not committed. Re-add indexers/download
  clients and their API keys in the web UIs after a restore (the UI generates
  a fresh API key for the app itself).

## Restore flow after a disk/host failure

1. Install the OS, clone this repo, copy `.env.example` → `.env` and fill in.
2. `python3 scripts/create_dirs.py`
3. Copy this `data/` tree back onto the drive: `cp -a data/ $ROOT_DIR/`
4. `docker compose up -d`
5. Re-enter credentials/tokens in each app UI (not stored here on purpose).
6. Optionally re-run `scripts/sync.sh` to create the full local backup again.
